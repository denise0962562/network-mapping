# 扫描结果统一存储于 Elasticsearch 的实施方案

状态：待实施方案；2026-09-06 根据当前代码与文档制定。本文不表示生产迁移、恢复演练或性能验收已经完成。

## 1. 目标与边界

扫描原始事实以 ES 为唯一权威来源，资产、搜索、任务结果和导出统一使用 ES 扫描读路径。PG 保留业务状态、上传回执、补偿队列和紧凑分析快照。迁移完成后退役正常运行中的 PG 扫描事实后端与旧搜索副本，减少长期维护的分支。

本方案假设后续正式部署均具备 ES，不再将“无需 ES 的独立部署”作为长期兼容目标。本次只制定方案，不修改运行配置、不迁移或删除数据、不发布版本。

| 数据 | 目标存储 | 处理原则 |
|---|---|---|
| IP、端口、协议、服务、banner、原始 evidence、观察时间 | ES observation | 保留原始证据，可审计、可重建派生投影 |
| 每次执行的端点结果、全局/用户当前资产 | ES endpoint 投影 | 从已提交事实重建，不能作为原始证据替代品 |
| DNS 查询证据、当前 RR 记录 | 现有 ES DNS 存储 | 纳入迁移、幂等、保留和恢复验收 |
| 用户、会话、权限、扫描器、任务及执行状态、标签定义与关联 | PG | 继续使用现有事务及约束 |
| 上传批次、内容校验和、实际索引引用 | PG `scan_result_batch` | 不保存完整结果正文，承担提交与重试身份 |
| 投影与标签同步待办、分析待办 | PG outbox | 保留失败重试和对账能力 |
| `analytics_*` 紧凑统计及水位 | PG | 派生数据；保留现有快照优化，按 ES 事实重建 |
| DNS 派生任务生成状态、去重地址、任务血缘 | PG | 属于调度所需状态，逐项确认用途，不能因名称含 DNS 就删除 |
| 旧 `scan_observation`、`ips`、`ports`、PG 当前端点投影 | 迁移期保留 | 验收后停止维护，清理单独执行 |

“唯一事实源”允许 ES 内存在多个派生索引，也允许 PG 保存计数与统计；禁止正常运行时继续在 PG 保存另一套完整扫描正文。

## 2. 现有基础与实施缺口

已有能力：`ScanStorageMode` 三种模式；ES 原始观察及端点投影；上传确定性身份和校验和；PG pending 回执；执行完成与 outbox 同事务；历史迁移和启动切换检查；ES 查询路径；PG 分析快照。

主要入口：`src/config.rs`、`src/lib.rs`、`src/elasticsearch.rs`、`src/search_projection.rs`、`src/analytics_snapshot.rs`、`src/handlers/{search,assets,task,data_saa,tags,operations}.rs`、`source/database/init.sql`。实施时通过调用关系确认完整范围，不按此列表机械删除文件。

需要补齐或核验的工作：

1. 建立全部扫描接口的读写依赖清单，区分业务元数据读取和旧事实回退。
2. 验证已有 ES 能力在真实迁移数据、故障和权限场景下正确；文档描述不替代集成验收。
3. 定义结果提交与投影可见性的独立状态，完善积压可观测性及重建入口。
4. 验证 DNS Data Stream 滚动后的重复上传身份，不能直接套用月度索引的幂等结论。
5. 完成跨 PG/ES 的配对恢复方案，明确原始事实过期后的历史与重建边界。
6. 最后收敛配置、移除 PG 事实读写及旧搜索副本；保留迁移工具与必要 outbox。

## 3. ES 数据组织

沿用已有命名和 mapping，不在存储收敛时同时重做数据模型：

| 索引/数据流 | 职责 |
|---|---|
| `network-mapping-scan-observations-v1-YYYY.MM` | 不可变扫描观察，按扫描器 `observed_at` 定位月份 |
| `network-mapping-execution-endpoints-v1` | 执行内端点投影 |
| `network-mapping-endpoints-current-v2` | `global/user` 权限范围的当前端点 |
| `network-mapping-dns-observations` | DNS 查询证据 Data Stream |
| `network-mapping-dns-records-v1` | 当前 DNS RR 投影 |
| `network-mapping-assets-v1` | 旧 PG 搜索副本，迁移后退役 |

必须保持以下数据契约：

- 保留 execution、task、scanner、user、upload、batch 身份以及原始观察时间。幂等 ID 和校验和算法沿用现有版本，改变时必须提供兼容迁移。
- IP 与 CIDR 分别使用现有 `ip` / `ip_range` 字段；IPv4、IPv6、单主机 CIDR 规范化行为一致。
- 原始 evidence 保留在 `_source`，只索引明确用于查询的字段，避免任意 JSON 扩张 mapping。
- 月度事实重试写入相同具体索引；不将其直接换为会滚动的写别名。DNS 单独验证跨 backing index 重试，若现有机制不足，先补稳定定位/去重协议再切换。
- 当前投影必须定义乱序处理：旧执行重试不能覆盖更新观察；同时间观察有稳定决胜规则。沿用已验证语义并添加跨执行重试测试。
- 索引结构升级和重建使用独立目标与校验后切换；不得直接覆盖唯一事实源。别名化可另行实施，不是首次切换前提。

## 4. 写入与完成语义

保留现有提交顺序，不把 ES 网络请求放回 PG 长事务：

1. 扫描器先持久化稳定上传身份、正文和下一批序号，失败或重启后重发同一批次。
2. 服务端校验扫描器、执行归属、批次身份和校验和，在短 PG 事务内预留 `pending` 回执，提交并释放连接及行锁。
3. 写 ES 原始事实和执行投影。逐项校验 Bulk；原始观察的 409 必须回读确认内容相同。网络超时视为结果未知，走幂等重试。
4. ES 成功后重新打开 PG 短事务，确认回执身份和执行状态，记录实际索引引用并完成回执。空结果批次也必须能完成。
5. final 必须通过连续批次、唯一 final、无未完成批次及执行计数校验。ES 查询可见性必须覆盖整个执行涉及的索引，不能仅依赖最后一个 Bulk 触及的分片。
6. 同一 PG 事务提交执行成功、任务聚合状态、投影 outbox 和分析 outbox。
7. PG 提交后发布当前端点投影；失败由 outbox 重试。扫描器只有收到协议约定的成功响应后才能清理对应待上传缓存。

`succeeded` 表示事实与回执已提交，不承诺全部搜索投影、标签或分析快照同时刷新。需要为接口提供投影是否就绪/是否滞后的明确信息；复用已有状态，缺少时再新增最小字段。不能把“索引不可用”表现为空结果。

| 故障点 | 必须达到的结果 |
|---|---|
| PG 预留后、ES 写入前退出 | pending 可被同身份重试接续 |
| ES 部分成功或成功后响应丢失 | 不提交完成回执；重试不重复事实、不放过内容冲突 |
| ES 成功、PG 确认失败 | 同身份重试安全收敛，不丢失已写事实 |
| PG 已成功、当前投影发布失败 | 保留成功事实及 outbox，恢复后发布，不伪造原子可见性 |
| ES 429、不可用、磁盘限制 | 有界并发、退避、告警、扫描器持久缓存与积压上限；不回退写 PG 事实 |
| 永久 mapping/内容冲突 | 明确记录不可重试原因，停止无意义重试并可人工修复 |

## 5. 读取与派生数据

| 功能 | 目标读取路径 | 验收重点 |
|---|---|---|
| 简单/高级搜索 | ES 当前投影 | 布尔、否定、跨端点条件、排序、总数和权限 |
| 资产概览、端口、历史 | ES 当前/执行投影及事实 | 地址规范化、历史顺序、跨用户隔离 |
| 任务详情和导出 | PG 元数据 + ES 执行结果/事实 | 零结果、完整导出、无重复或截断 |
| DNS 查询与对比 | ES DNS 证据与 RR | 历史对比不读取可变当前记录冒充历史 |
| 分布及热力图 | PG 已发布分析快照 | 后台从 ES 构建，保留统计口径和水位含义 |
| 标签 | PG 权威关联 + ES 投影 | 更新失败重试、并发更新后最终一致 |

所有 ES 查询统一在服务端添加权限过滤，不能接受客户端直接指定任意用户范围。查询超时、失败分片、异常游标或缺失预期索引必须失败关闭；合法空库与数据丢失必须区分。

导出和后台全量遍历采用有界分页及一致读取机制，逐执行核对预期观察数；现有查询限制必须显式保留或独立优化，不能为了切换静默截断。分析快照保留 `shadow → snapshot` 验收流程，不为了“全 ES”恢复请求时全量聚合。

## 6. 分阶段实施及退出条件

### A. 盘点与建立基线

记录服务端/扫描器/前端提交、实际存储模式、ES 版本及模板、节点拓扑、索引和 PG 表规模、成功执行及批次数量、pending/outbox、当前备份与恢复能力。配置记录必须脱敏。

选取 IPv4/IPv6/CIDR、DNS、多扫描器、空执行、重复上传、标签变更、普通用户和管理员作为固定验收集。记录搜索/导出/分析的正确性和 P95 延迟、峰值写入量、单日主分片增量。

退出条件：形成可重复的接口基线、事实清单和容量报告。阶段 A 不删除数据。

### B. 加固现有 ES 路径

按第 4、5 节补集成测试与故障注入；核验投影幂等、跨批次可见性、DNS 滚动重试、任务取消/租约变化期间上传、后台对账和重建。保留现有三种模式以便迁移。

新安装空库需要独立、幂等的 ES 初始化路径：验证无旧事实后生成空基线，不要求伪造历史迁移；现有启动门禁是否支持此路径必须测试。

退出条件：故障矩阵、权限测试及配对备份恢复演练通过，确认部署容量满足写入与查询要求。

### C. 历史迁移与对比

复用 [现有迁移流程](ELASTICSEARCH.md)，由 `postgres` 进入 `dual`，在受控维护窗口停止常规服务，运行已有 `--migrate-scan-data-to-elasticsearch`。记录迁移批次范围、失败项、校验和及索引引用；修复后原身份重跑。

不能仅比较总文档数：全量核对执行/批次计数和校验和，分开核对去重投影计数；对固定验收集比较规范化结果、权限、分页和导出。单独列出旧版本、缺回执、未完成任务和 DNS 数据覆盖情况，不能默认迁移命令覆盖所有历史形态。

`dual` 读取仍走 PG 或旧搜索副本，不能把该模式下页面正常当作新 ES 读路径通过。使用同一静态备份构建隔离 ES 模式验收环境，或在受控冻结窗口完成切换验证。

退出条件：范围内差异为零或已解释并修复；无阻塞 pending/投影待办；新读路径验收通过；生成配对恢复点。

### D. 正式切换 ES

在维护窗口冻结结果提交和会修改相关数据的后台任务，完成最终增量核对与配对备份。部署操作按既有发布治理另行授权。

使用现有配置 `enabled=true`、`read_enabled=true`、`scan_storage="elasticsearch"`、`fallback_to_postgres=false`；启动门禁通过后恢复服务。保留旧 PG 事实及兼容版本作为观察期恢复材料。

验收至少覆盖一个完整业务扫描周期；建议观察 7–14 天，最终长度按任务周期确定。期间新 PG 事实写入为零，ES 新事实与回执相符，补偿积压可收敛，权限/导出/分析正确，恢复演练达标。

### E. 收敛代码与清理历史

先收敛运行路径，再清理数据，拆成独立变更：

1. 正常运行固定 ES 事实读写，移除 PG 回退、旧副本全量同步和多模式业务分支；历史迁移保留在独立入口。
2. 配置迁移显式拒绝未迁移旧部署，给出操作提示，不忽略旧配置后启动空数据服务。
3. PG `asset_endpoint_current` 和旧搜索索引只在确认无读写依赖后退役；`search_index_outbox` 仍可能承担标签同步，拆分职责后再判断能否删除。
4. `analytics_*`、上传回执、任务关联和 DNS 调度状态继续保留；初始化 SQL 随退役调整，避免重启重新创建已退役事实表。
5. 历史表归档、空间回收和旧 ES 索引删除单独制定可预览清单，在保留期及恢复要求满足后执行。

退出条件：正常请求和 worker 无旧事实依赖，新安装及旧库升级均通过测试，迁移工具仍能读取保留的旧 schema。

## 7. 容量、保留与恢复

生产维持现有至少一份副本、活动分片检查和 request 级 translog 持久化要求。节点故障时写入是否等待副本恢复必须实测，不能把副本存在视为无条件可写。主节点仲裁和数据节点故障域一并纳入部署设计。

容量以实测单日主分片增长 × 在线保留天数 ×（1 + 副本数）为基础，再加投影、merge/reindex 临时空间及磁盘水位余量；快照仓库另计。未知数据量时不预设分片数或硬件规格。监控 Bulk 延迟/拒绝/条目失败、pending 年龄、outbox 年龄、PG 锁等待、磁盘及分片健康、快照新鲜度、分析水位。

第一阶段不缩短现有保留期。原始事实过期会影响历史查询、全量统计重算和投影重建：先定义在线/归档边界，保存可恢复快照，再允许删除。若当前投影含早于在线事实保留范围的端点，重建必须使用归档或完整基线，不能仅用在线事实重建后宣称完整。DNS 保留也需遵守同样规则。

ES 快照不是所有分片的同一时间点，也不会与 PG 备份自动组成跨库事务。[Elastic 快照说明](https://www.elastic.co/docs/deploy-manage/tools/snapshot-and-restore#snapshot-start-and-stop-times)。首次切换采用可验证的冻结恢复点：

1. 暂停调度、上传提交、标签写入及相关后台写入，等待在途请求结束；明确处理 pending，排空投影/分析待办或记录其可恢复集合。
2. 记录数据库身份、执行/批次清单与校验和、模板版本、具体索引清单和应用提交；冻结期间完成 PG 备份及 ES 快照并确认成功。
3. 在隔离环境恢复同一对备份，核对回执指向的事实、内容和计数；重建或补偿派生数据后验收，再恢复正常写入。

日常继续分别备份 PG 和 ES，但必须明确共同恢复边界与丢失窗口。生产切换前通过演练确定 RPO（可接受数据丢失窗口）和 RTO（恢复时限）的具体数值；未验证的目标不能视为已保证。

扫描器缓存不是长期备份，成功响应后可能已清理；无法从快照或归档恢复的已确认事实必须报告损失，不能只修改 PG 成功状态掩盖。ES 中孤立的未确认事实先隔离对账，不自动当作完成任务发布。

## 8. 回滚与验收交付

切换前可继续 PG/dual。切换后优先回滚到已验证且支持 ES 权威模式的服务版本，保持存储模式不变。

若必须回 PG，先停写，提供并验证 ES-only 增量反向回填（包括批次、观察、IP/端口关系和派生重建），完成全量核对后才可改模式。当前已有正向迁移命令不代表已经具备反向迁移工具；工具未经演练时只能使用配对恢复点并明确其后的数据损失窗口，禁止直接改配置假回滚。

实施交付拆为五项：依赖/基线报告；写入与查询故障测试及修复；迁移对账与恢复工具；切换验收报告；兼容路径退役和归档清理方案。服务端为主要改动仓库；扫描器仅在身份/缓存/重试契约有缺口时修改；前端仅按需要展示投影延迟和错误，保持现有 UI 风格。

每项实现运行对应 Rust 组件的 `cargo fmt --check`、`cargo clippy --all-targets`、`cargo test` 及构建，并运行依赖真实 PG/ES 的集成验收。前端变更运行 `pnpm build` 并人工检查相关路由。测试失败或基础设施缺失必须记录为未通过。

最终上线门槛：迁移内容无未解释差异；相同批次重试不增量、不同内容被拒绝；空批次/跨月/IPv6/DNS/并发及取消正确；故障恢复后提交和投影收敛；权限无串读；完整导出无截断；PG 不再新增完整事实；配对恢复达到已确定 RPO/RTO；代表性负载性能达到阶段 A 记录并冻结的目标。
